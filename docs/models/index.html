模型清单以实际返回为准

生成前先确认本机现有的模型，而不是照抄任何历史清单：

curl -s http://127.0.0.1:8771/ollama/api/tags
  • 历史上工作台用的是 gemma4:12b 这类可 chat 的模型；26b 不能 chat，latest 是 8B 小模型。
  • 选模型时以 /ollama/api/tags 返回的真实列表为准，只选能 chat 的。
已知状态2026-11-06 曾发生本地 Ollama 模型与权重被误删、连接断线的事故。在明确恢复之前，不要假设旧模型清单仍然有效，也不要擅自重新下载或重启服务。

验证顺序

  1. 页面能打开，且顶部有 v2 已清理 标识。
  2. /ollama/api/tags 有返回，且列表里有可 chat 的模型。
  3. 单镜生成能返回 8 行文本，再开始批量。

任何一步断了，先看 常见问题；环境拓扑见 本地环境与部署。

请求里只发什么

工作台生成卡片时，请求体只包含本镜剧情，不附带整体剧情、全局锚定、输出结构说明或风格预设：

【本镜分镜剧情】
范富贵站在古旧青瓦屋顶上，脚下一滑，身体歪着晃了两下。
为什么旧版把常量层、技术标签一起塞进请求，会把输出带偏成带标签的长段落；8 行规格要求输出本身就是成品，不再需要外挂说明。
